# 1.3 Скрипт проверки

## Цель

Одна команда `scripts/check.sh` запускает проверку форматирования, clippy с запретом предупреждений и тесты. При любой ошибке код возврата ненулевой. Этот же скрипт потом вызывает CI (шаг 1.4).

## План

- Новый `scripts/check.sh` (bash, исполняемый): `set -euo pipefail`, переход в корень репозитория, затем `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace`. Остановка на первой ошибке, порядок от быстрой проверки к долгой.
- `cargo-nextest` не берём: тест один, а nextest это отдельная установка на трёх системах в CI и он не запускает doc-тесты. Решение записать в `docs/decisions.md`.
- `README.md`, раздел «Проверка»: три команды заменить на скрипт. Код Rust не меняется.
- Рекомендуемая модель: старшая, потому что веха 1 целиком идёт на ней; по сложности хватило бы средней.
- Риски: на Windows скрипт работает только в Git Bash (в GitHub Actions он есть).
- Альтернатива: `cargo xtask` на Rust. Переносимее, но это новый крейт ради трёх команд.

## Тесты

Автотестов нет. Проверка руками на копии проекта во временной папке:

1. Чистый проект: три заголовка, код возврата 0.
2. Испорченное форматирование: падает на `fmt`.
3. Предупреждение (неиспользуемая переменная): падает на `clippy`.
4. Падающий тест: падает на `test`.
5. Запуск из `crates/sim`: работает.

## Итог

Сделано по плану. Отличие: по решению автора в `CLAUDE.md` (раздел «Команды») добавлена строка про скрипт. В `decisions.md` решение № 20, вопрос про nextest убран из «Открытых».

- Выполнено на модели: старшая (Claude Fable 5.2).
- Вывод проверок (`scripts/check.sh` на рабочем проекте, код возврата 0):
  `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy`: `Finished dev profile`; `== 3/3 Тесты`: `test tests::tick_rate_is_fixed ... ok`, `test result: ok. 1 passed; 0 failed`; `== Все проверки прошли`.
- Случаи на копии: 2 → код 1 (diff от rustfmt), 3 → код 101 (`unused variable`, `-D warnings`), 4 → код 101 (`test result: FAILED`), 5 → код 0.

## Новое в Rust

Кода Rust в шаге нет. Из инструментов: `cargo fmt --check` ничего не меняет, только сообщает о расхождениях; `-D warnings` превращает предупреждения в ошибки.

## Открытые вопросы

- На Windows скрипт не проверялся, первая проверка будет в CI на шаге 1.4.
- Скрипт останавливается на первой ошибке, остальные проверки не запускаются. Если в CI захочется видеть все ошибки сразу, это решается отдельными шагами workflow.
- В репозитории ещё нет ни одного коммита, ветка шага не создана.
