# 1.4 CI

## Цель

При каждом push в `master` и в каждом pull request GitHub Actions запускает `scripts/check.sh` на macOS, Windows и Linux. Отдельная проверка не пропускает `todo!` в коде.

## План

- Новый `.github/workflows/ci.yml`, две задачи (job):
  - `check`: матрица `ubuntu-latest`, `macos-latest`, `windows-latest`, `fail-fast: false` (падение на одной системе не отменяет остальные, видно всю картину). Шаги: `actions/checkout`, установка Rust через `rustup toolchain install` (версию и компоненты берёт из `rust-toolchain.toml`, rustup уже есть на раннерах), кеш, `scripts/check.sh` с `shell: bash` (на Windows это Git Bash).
  - `no-todo`: только Linux, запускает `scripts/check-todo.sh`.
- Новый `scripts/check-todo.sh`: `grep -rn` по `crates/` в файлах `*.rs` ищет `todo!` и `unimplemented!`; нашёл → печатает строки и код возврата 1. В `check.sh` не входит: во время работы над шагом `todo!` разрешён, в `master` нет.
- Новый `.gitattributes`: `* text=auto eol=lf`. Без него git на Windows отдаёт `check.sh` с переводами строк CRLF, и bash на нём падает.
- Кеш сборки: `Swatinem/rust-cache@v2` (сторонний action, фактический стандарт для Rust; сам строит ключ из `Cargo.lock` и версии компилятора). **Нужно согласие**, это внешняя зависимость.
- `README.md`: строка про CI и `check-todo.sh`. Код Rust не меняется.
- Рекомендуемая модель: старшая (веха 1 целиком на ней); по сложности хватило бы средней.
- Риски: у репозитория нет `origin`, поэтому сам workflow я запустить не могу, первая настоящая проверка после push автором. В приватном репозитории минуты macOS считаются ×10, Windows ×2 (лимит бесплатного плана 2000 в месяц).
- Альтернативы:
  - `todo!` ловить линтом `clippy::todo` в `[workspace.lints]` вместо grep: точнее (не срабатывает на комментарии и строки), но тогда `check.sh` падает и во время работы, а спецификация просит отдельную проверку.
  - Кеш на `actions/cache` с ключом вручную: без стороннего action, но 10-15 строк YAML, которые легко написать неправильно.

## Тесты

Автотестов нет. Локально, на копии проекта во временной папке:

1. `check-todo.sh` на чистом проекте: код 0.
2. Добавлен `todo!()` в `crates/sim/src/lib.rs`: код 1, в выводе файл и номер строки.
3. `unimplemented!()`: код 1.
4. Запуск из `crates/sim`: работает.
5. `scripts/check.sh` на рабочем проекте проходит.

После push (делает автор):

6. Обе задачи зелёные, `check` на трёх системах.
7. Ветка с `todo!`: `no-todo` красная, `check` зелёная.
8. Повторный запуск: в логе видно, что кеш восстановлен.
