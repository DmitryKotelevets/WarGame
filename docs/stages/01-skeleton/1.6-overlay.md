# 1.6 Оверлей

## Цель

В левом верхнем углу окна видны две строки: FPS и номер тика. Тик это счётчик в клиенте, который растёт 30 раз в секунду (`sim::TICKS_PER_SECOND`) независимо от частоты кадров.

## План

- Новый `crates/client/src/overlay.rs`:
  - ресурс `TickCounter { tick: u64 }`: временный счётчик. В вехе 2 его заменит номер тика из мира симуляции;
  - компонент-метка `OverlayText`, чтобы система обновления находила именно этот текст;
  - `setup` (расписание `Startup`): создаёт узел интерфейса `Node` с `PositionType::Absolute`, отступ 8 px от левого и верхнего края, `Text`, `TextFont` размером 18 px, белый `TextColor`;
  - `advance_tick` (расписание `FixedUpdate`): прибавляет 1 к счётчику;
  - `update_text` (расписание `Update`): читает FPS из `DiagnosticsStore` и счётчик, записывает строку в `Text`;
  - обычная функция `overlay_text(fps: Option<f64>, tick: u64) -> String`: собирает текст. Вынесена отдельно, чтобы её можно было проверить без окна.
- `crates/client/src/main.rs`: `mod overlay;`, плагин `FrameTimeDiagnosticsPlugin::default()` (он считает FPS, сам ничего не рисует), ресурс `Time::<Fixed>::from_hz(...)` с частотой из `sim::TICKS_PER_SECOND`, регистрация трёх систем.
- Как работает `FixedUpdate`: Bevy копит прошедшее время и запускает расписание столько раз, сколько тиков в него поместилось. При 60 кадрах в секунду это один тик на два кадра, при просадке кадров несколько тиков за кадр. Так же будет запускаться настоящий `step()` в вехе 2.
- FPS берётся сглаженный (`smoothed()`), округляется до целого. Пока измерений нет, показывается `FPS: --`.
- Надписи на английском: `FPS: 60` и `Tick: 123` (решение № 22: все тексты, которые видит игрок, на английском). По тому же решению заголовок окна в `main.rs` меняется с `RTS (рабочее название), симуляция v1` на `RTS (working title), sim v1`.
- `f64` здесь допустим: запрет на float действует только в `crates/sim`.
- API сверен с исходниками Bevy 0.20.1 в локальном реестре cargo (`bevy_diagnostic`, `bevy_time`, `bevy_ui`, пример `examples/ui/text/text.rs`). Новых крейтов нет.
- Рекомендуемая модель: старшая (веха 1 целиком на ней); по сложности хватило бы средней.
- Риски: на Mac кадры ограничены частотой экрана, FPS будет 60 или 120, а не «сколько может видеокарта». Это ожидаемо.
- Альтернативы:
  - Готовый `FpsOverlayPlugin` из `bevy_dev_tools`: меньше кода, но нужна дополнительная возможность Bevy, и номер тика он не покажет, второй текст всё равно писать самим.
  - Тип `Tick` сразу в `sim`: спецификация вехи запрещает логику в `sim`, а формат идентификаторов решается в вехе 2.

## Тесты

Один автотест в `overlay.rs` на функцию `overlay_text`: с измеренным FPS (`Some(59.6)`, тик 123 → `FPS: 60` и `Tick: 123`) и без измерений (`None` → `FPS: --`).

Проверяю сам: `scripts/check.sh` проходит; клиент работает 10 секунд без паники и без слова `error` в логе.

Автор должен увидеть после `cargo run -p client`:

1. В левом верхнем углу две белые строки поверх сцены, текст читается на фоне неба и земли.
2. FPS около частоты экрана (60 или 120), число не мелькает.
3. Номер тика растёт равномерно: через 10 секунд после запуска около 300.
4. При изменении размера окна текст остаётся в углу. Сцена из шага 1.5 не изменилась.

## Итог

Сделано по плану. Отличие: `update_text` записывает строку в `Text` только когда она изменилась. Причина: любая запись заставляет Bevy заново раскладывать буквы, а тик меняется реже, чем кадр. Попутно записано решение № 22 (тексты для игрока на английском): строка в `docs/decisions.md` и в `CLAUDE.md`, заголовок окна теперь `RTS (working title), sim v1`.

- Выполнено на модели: старшая (Claude Fable 5.2).
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy`: `Finished dev profile`; `== 3/3 Тесты`: `test overlay::tests::shows_rounded_fps_and_tick ... ok`, `test overlay::tests::shows_dashes_until_fps_is_measured ... ok`, `test tests::tick_rate_is_fixed ... ok`; `== Все проверки прошли`.
- Запуск на Mac (M4 Max, Metal): процесс жив через 14 секунд, в логе `Creating new window RTS (working title), sim v1`, слов `panic`, `error`, `warn` нет.

## Новое в Rust

- `#[derive(Resource, Default)]`: компилятор сам пишет реализацию указанных трейтов. `Default` даёт значение по умолчанию (для `u64` это 0), `Resource` и `Component` разрешают Bevy хранить тип.
- `pub struct OverlayText;`: структура без полей. Значения в ней нет, важен только сам тип.
- `Option<f64>`: значение, которого может не быть. `Some(x)` это «есть», `None` это «нет»; `match` обязывает разобрать оба случая.
- `{fps:.0}` в `format!`: число печатается с нулём знаков после запятой, с округлением.
- `f64::from(x)`: преобразование типа, которое не может потерять данные. Для преобразований с потерей компилятор такой функции не даёт.
- `#[cfg(test)] mod tests` внутри файла клиента: модуль компилируется только при `cargo test`.
- `Single<&mut Text, With<OverlayText>>`: параметр системы Bevy, изменяемый доступ к компоненту `Text` единственного объекта с меткой `OverlayText`.

## Открытые вопросы

- Пункты 1-4 из «Тестов» агент не видел: окно проверяет автор. Что текст вообще появился на экране и что тик идёт 30 раз в секунду, автоматически не проверено.
- `TickCounter` это заглушка. В вехе 2 его заменяет номер тика из мира симуляции, а `advance_tick` заменяется вызовом `step()`.
- Поведение при долгой паузе (окно свёрнуто, отладчик) не настраивалось: Bevy сам ограничивает, сколько тиков догонять за кадр. К настоящей симуляции это нужно решить явно.
- Причину решения № 22 сформулировал агент, автор её не подтверждал.
- Windows и Linux не проверены (шаг 1.4 пропущен).
