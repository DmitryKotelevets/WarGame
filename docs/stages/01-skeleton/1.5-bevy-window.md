# 1.5 Окно Bevy

## Цель

`cargo run -p client` открывает окно: плоскость земли, свет солнца, неподвижная камера сверху под углом. Версия Bevy зафиксирована точно и записана в `docs/decisions.md`.

## План

- Версия: Bevy **0.20.1** (последняя стабильная на crates.io на 2026-11-23). В `crates/client/Cargo.toml`: `bevy = "=0.20.1"`, знак `=` запрещает cargo брать другую версию. Набор возможностей (features) по умолчанию, ничего не отключаем.
- Bevy 0.20.1 требует Rust 1.97.1, у нас в `Cargo.toml` заявлен 1.85. Поднимаю `rust-version` до `1.97.1` (локально стоит 1.100), правлю строку в `README.md`.
- `crates/client/src/main.rs`: `App::new()`, `DefaultPlugins` с заголовком окна, регистрация системы `scene::setup` в расписании `Startup`.
- Новый `crates/client/src/scene.rs`, одна функция `setup`: создаёт
  - плоскость 100×100 м (`Plane3d`, однотонный материал);
  - `DirectionalLight` с тенями, наклонён как солнце после полудня;
  - `Camera3d` на высоте около 40 м под углом примерно 55° к земле, смотрит в центр.
  Числа вынесены в константы с комментариями. Пишу обычным `commands.spawn((...))`, без нового макроса `bsn!` из примеров 0.20: он короче, но скрывает, что происходит.
- Быстрая сборка: в `client` возможность `dynamic_linking = ["bevy/dynamic_linking"]`, по умолчанию выключена. Запуск в разработке: `cargo run -p client --features dynamic_linking`. `check.sh` и будущие релизные сборки её не включают.
- `docs/decisions.md`: решение № 21 (версия Bevy и минимальный Rust), вопрос убирается из «Открытых».
- API сверяю с docs.rs и примерами именно 0.20.1, не по памяти.
- Рекомендуемая модель: старшая (веха 1 целиком на ней).
- Риски: первая сборка Bevy занимает несколько минут и около 10 ГБ в `target`; `Cargo.lock` вырастет на тысячи строк (генерируется, читать не нужно). Динамическая линковка на Windows и Linux не проверена: шаг 1.4 пропущен, CI нет.
- Альтернативы:
  - Отключить ненужное сразу (2D, звук Bevy, геймпад): сборка быстрее, но список возможностей придётся подбирать и объяснять. Предлагаю отдельным шагом, когда сборка начнёт мешать.
  - Динамическая линковка через алиас в `.cargo/config.toml` (`cargo dev`): короче команда, но ещё один файл настроек.

## Тесты

Автотестов нет (клиент). Проверяю сам: `scripts/check.sh` проходит; клиент запускается и работает 10 секунд без паники, в том числе с `--features dynamic_linking`.

Автор должен увидеть после `cargo run -p client`:

1. Окно с заголовком игры.
2. Плоскость занимает большую часть кадра, виден её дальний край и фон за ним.
3. Плоскость освещена, не чёрная и не пересвеченная.
4. Камера смотрит сверху под углом, как в RTS. Управления нет (это веха 3).
5. Закрытие окна завершает программу без ошибок в терминале.

## Итог

Сделано по плану. Отличие: в заголовок окна добавлена версия симуляции (`sim::SIM_VERSION`). Причина: после замены заглушки клиент перестал использовать крейт `sim`, и cargo выдал предупреждение `unused dependency`; убирать зависимость до шага 1.6 хуже, чем использовать её по делу. Второе отличие: плоскость 50×50 м вместо 100×100. По снимку автора плоскость 100 м закрывала весь кадр, дальнего края не было видно (ошибка в расчёте поля зрения камеры).

- Выполнено на модели: старшая (Claude Fable 5.2).
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy`: `Finished dev profile`; `== 3/3 Тесты`: `test tests::tick_rate_is_fixed ... ok`, `test result: ok. 1 passed; 0 failed`; `== Все проверки прошли`.
- Запуск на Mac (M2 Pro, Metal), обычный и с `--features dynamic_linking`: процесс жив через 12-15 секунд, в логе `Creating new window RTS (рабочее название), симуляция v1`, слов `panic` и `error` нет.
- Сборка: первая 5 мин 29 с, с динамической линковкой ещё 3 мин 13 с, `target` 12 ГБ.

## Новое в Rust

- `mod scene;` подключает файл `scene.rs` как модуль; `pub fn` делает функцию видимой из других модулей.
- `use bevy::prelude::*` вносит в область видимости все имена из набора «самое нужное» крейта.
- `Window { title: ..., ..default() }`: остальные поля берутся из значения по умолчанию.
- `format!("{GAME_TITLE}, v{}", x)` собирает строку; имя в фигурных скобках подставляет переменную.
- `ResMut<Assets<Mesh>>`: тип с параметром в угловых скобках. Здесь это изменяемый доступ к хранилищу мешей; Bevy сам передаёт его в систему по типу аргумента.
- `commands.spawn((A, B))`: кортеж в скобках, набор компонентов одного объекта.
- `[features]` в `Cargo.toml`: именованные переключатели сборки, включаются флагом `--features`.

## Открытые вопросы

- Пункты 1-4 из «Тестов» подтверждены снимком экрана автора (после уменьшения плоскости до 50 м). Сам агент окно не видит: на запись экрана у сессии нет разрешения.
- Земля на экране светлее и бледнее заданного цвета `GROUND_COLOR`. Не пересвечена; подстройка света отложена до появления первых объектов.
- Windows и Linux не проверены совсем, динамическая линковка тоже (шаг 1.4 пропущен). Системные библиотеки Linux для CI переходят в шаг 1.4.
- Тени включены, но отбрасывать их нечему до первого куба (шаг 2.14).
- Подключены все возможности Bevy по умолчанию (2D, звук, геймпад). Отключение лишнего это отдельный шаг.
- Закрытие окна (пункт 5) не проверено: процесс я завершал сигналом.
