# Веха 1. Каркас проекта

## Что должно заработать

Пустой, но полностью настроенный проект: одна команда проверяет код,
CI собирает его на трёх системах, клиент открывает окно с плоскостью
и показывает номер тика.

Игровой логики в этой вехе нет. Её цель: проверить процесс работы
(файл шага, план, остановка, итог) на простых задачах.

## Уже сделано

- 1.1 Workspace с крейтами `sim`, `client`, `tools`, один тест.
- 1.2 Документы: `CLAUDE.md` и папка `docs`.

Эти два шага выполнены при создании скелета, файлов шагов для них нет.

## Шаги

### 1.3 Скрипт проверки

`scripts/check.sh`: форматирование в режиме проверки, clippy с запретом
предупреждений, тесты. Ненулевой код возврата при любой ошибке.
Решено: `cargo-nextest` не используем (решение № 20 в `docs/decisions.md`).

### 1.4 CI

GitHub Actions с матрицей macOS, Windows, Linux: запуск скрипта проверки.
Кеширование сборки. Отдельная проверка, что в коде нет `todo!`.

### 1.5 Окно Bevy

- Выбрать актуальную стабильную версию Bevy, зафиксировать её точно
  и записать в `docs/decisions.md`.
- Окно с плоскостью, направленным светом и камерой сверху под углом.
- Настроить быструю отладочную сборку (динамическая линковка Bevy
  в разработке, если работает на всех трёх системах).
- Для Linux в CI понадобятся системные библиотеки, их нужно добавить
  в сценарий.

### 1.6 Оверлей

FPS и номер тика в углу экрана. Тик пока просто счётчик, который
увеличивается 30 раз в секунду (`sim::TICKS_PER_SECOND`), настоящая
симуляция появится в вехе 2.

## Чего не делаем

- Никакой игровой логики в `sim`.
- Никаких моделей, текстур, звука.
- Никакого управления камерой (это веха 3).

## Критерии готовности

- `scripts/check.sh` проходит локально.
- CI зелёный на macOS, Windows и Linux.
- `cargo run -p client` открывает окно на Mac, видна плоскость,
  в углу FPS и растущий номер тика.
- Версия Bevy записана в `docs/decisions.md`.
- На каждый из шагов 1.3-1.6 есть заполненный файл шага.
