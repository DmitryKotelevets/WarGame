# 2.6 Хеш состояния мира

## Цель

`World::hash()` сворачивает всё состояние мира в одно число. Два мира с одинаковым состоянием дают одинаковый хеш на любой платформе, а любое отличие в состоянии хеш меняет. На этом будут стоять тест детерминизма (2.11) и проверка реплея (2.12).

## План

- Новый `crates/sim/src/hash.rs`:
  - `pub struct StateHasher { state: u64 }` с методами `new()`, `write_u8`, `write_bool`, `write_u32`, `write_u64`, `write_i64`, `finish() -> WorldHash`. Числа шире байта подаются по байтам в порядке от младшего (`to_le_bytes`): порядок записан явно и не зависит от процессора.
  - `pub struct WorldHash(u64)` (`Clone, Copy, PartialEq, Eq`), `raw() -> u64`, печать 16 шестнадцатеричными цифрами. Отдельный тип, чтобы хеш не путался с сидом и другими `u64`.
- **Алгоритм (нужно решение автора): FNV-1a на 64 бита.** Для каждого байта: «исключающее или» с состоянием, затем умножение на константу с заворачиванием. Две строки кода и две константы, алгоритм в общественном достоянии, есть опубликованные эталонные значения. Хеш нужен, чтобы заметить расхождение, а не для защиты от подделки, поэтому криптографическая стойкость не требуется.
- Что входит в хеш и в каком порядке (`World::hash` в `world.rs`): `tick`, состояние `rng`, затем юниты.
- Юниты (`UnitStore::hash_into` в `unit_store.rs`, потому что ячейки закрыты): число ячеек, затем каждая ячейка по порядку: поколение, отметка на удаление, признак «занята», и для занятой сам юнит. Свободные ячейки тоже хешируются: их поколения определяют будущие идентификаторы.
- Юнит (`Unit::hash_into` в `unit.rs`): `id.index`, `id.generation`, `position.x.raw()`, `position.y.raw()`.
- **Защита от забытого поля:** в каждой из трёх функций структура сначала разбирается на поля целиком (`let Unit { id, position } = *self;`). Если позже в структуру добавят поле и не добавят его в хеш, код перестанет компилироваться.
- **Эталонный хеш:** один тест с записанным числом для небольшого сценария. Он падает при любом изменении формата хеша или логики; менять число можно только с согласия автора, обычно вместе с `SIM_VERSION`. Число я получу из реализации и сверю независимым расчётом в Python по тому же списку байтов.
- `step()` хеш не считает: его вызывает тот, кому он нужен (тесты, `tools`, позже сеть). `SIM_VERSION` в хеш не входит: версия записывается в реплей отдельно (2.12).
- `lib.rs`: `pub mod hash;`. Новых крейтов нет. `SIM_VERSION` не меняется.
- Рекомендуемая модель: старшая (хеш).
- Риски:
  - `unit_store.rs` уже 471 строка, добавится около 25. Вопрос о лимите 400 строк из шага 2.3 остаётся открытым.
  - FNV-1a слаб против намеренного подбора и хуже перемешивает, чем современные хеши. Случайное совпадение двух разных состояний имеет вероятность порядка 2^-64, для поиска расхождений этого достаточно.
- Альтернативы:
  - `std::hash::Hash` через `#[derive(Hash)]`: меньше кода, но результат не обещан одинаковым между версиями Rust и платформами (спецификация вехи это запрещает).
  - Хеш через `Rng`-подобное перемешивание по 64 бита за раз: быстрее, но нет опубликованного эталона для сверки.
  - Хешировать только живых юнитов: проще, но два мира с разными поколениями в свободных ячейках выглядели бы одинаковыми и разошлись бы позже.

## Тесты

Сначала тесты, потом реализация.

1. Эталоны FNV-1a: пустой вход → `0xcbf29ce484222325`; байт `a` → `0xaf63dc4c8601ec8c`; байты `foobar` → `0x85944171f73967e8`.
2. `write_u32(0x04030201)` равен четырём `write_u8` от 1 до 4; то же для `write_u64` и `write_i64`; `write_bool` это байт 0 или 1. `WorldHash` печатается как 16 цифр с ведущими нулями.
3. Два мира, построенные одинаково, дают один хеш; повторный вызов `hash()` даёт то же число.
4. Хеш меняется от каждого отличия по отдельности: другой сид; сделан `step()`; взято число из `rng`; добавлен юнит; позиция (1, 2) против (2, 1); юнит отмечен на удаление; юнит родился и удалён против мира, где его не было (при равных тиках).
5. Эталонный хеш сценария: сид 2026, два юнита, один отмечен, 10 шагов.
6. `proptest`: одна и та же случайная последовательность действий (создать, отметить, шаг) над двумя мирами даёт равные хеши после каждого действия.

## Итог

Сделано по плану, алгоритм FNV-1a. Отличия:

- Эталонный сценарий чуть шире, чем в плане: три юнита вместо двух. Один удалён шагом (в хеш попадает свободная ячейка с поколением 1), другой отмечен после шагов (в хеш попадает отметка). Эталон `0x0676_4738_3605_609a`; то же число дал независимый расчёт в Python по выписанным вручную 86 байтам.
- Добавлены `WorldHash::from_raw` (нужен тесту с эталоном и будущему реплею) и ручной `impl Default for StateHasher` (требует clippy).
- Сверх списка тестов: порядок записи влияет на хеш; сдвиг координаты на один шаг сетки меняет хеш.
- Выполнено на модели: старшая (Claude Fable 5.2).
- Тесты до реализации: `cargo test -p sim` не собирался: `no method named hash found for struct World` (25 раз), `cannot find type StateHasher` (7 раз), `WorldHash`.
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy` без предупреждений; `== 3/3 Тесты`: в `sim` `test result: ok. 82 passed; 0 failed` (15 новых: 5 в `hash::tests`, 10 в `world::tests`), в `client` `2 passed`; `== Все проверки прошли`. `scripts/check-todo.sh`: заглушек нет.
- Размеры файлов: `hash.rs` 192 строки, `unit.rs` 54, `world.rs` 235, `unit_store.rs` 507 (код 200, тесты 307).

## Новое в Rust

- `let Unit { id, position } = *self;`: разбор структуры на поля. Перечислить нужно все поля, иначе ошибка компиляции; на этом построена защита от поля, забытого в хеше.
- `let Slot { generation, unit, marked_for_removal } = slot;`, где `slot` это ссылка: переменные тоже получаются ссылками, поэтому дальше `*generation`.
- `value.to_le_bytes()`: число как массив байтов от младшего к старшему, одинаково на любом процессоре.
- `self.state ^= x;`: короткая запись `self.state = self.state ^ x`.
- `u8::from(true)`: `bool` в число, `false` это 0, `true` это 1.
- `impl fmt::Display for WorldHash`: печать через `{}`; `{:016x}` означает шестнадцатеричный вид, ширина 16, слева нули.
- `fn finish(self)`: метод забирает значение целиком, после него накопителем пользоваться нельзя.
- `b"foobar"` и `b'a'`: строка и символ как байты; `&[u8]` это ссылка на последовательность байтов любой длины; `[0xff; 8]` это восемь одинаковых байтов.
- `impl Default for StateHasher { fn default() ... }`: `Default`, написанный вручную, когда выведенный автоматически дал бы неверное значение.

## Открытые вопросы

- `unit_store.rs` теперь 507 строк (код 200). Вопрос о лимите 400 строк из шага 2.3 всё ещё не решён.
- Защита от забытого поля работает только для полей структур. Если состояние появится вне `World` (глобальная переменная, значение внутри системы), хеш его не увидит.
- Хеш считается проходом по всем ячейкам и каждому байту. Скорость не измерялась; считать его каждый тик или реже, решают шаги 2.11 и 2.12.
- Один хеш на весь мир говорит, что прогоны разошлись, но не говорит где. Хеши по системам отложены до сети (после 1.0).
- FNV-1a не защищает от намеренной подделки. Для античита в сети понадобится другой алгоритм.
- Эталон проверен только на macOS (ARM). Совпадение на Windows и Linux покажет CI при первом push этой ветки.
- Спецификация вехи 2 всё ещё не утверждена автором.
