# 2.1 Тип `Fixed`

## Цель

В `crates/sim` есть тип `Fixed`: число с фиксированной точкой и четыре действия арифметики, результат которых одинаков на любом процессоре. Формат числа записан в `docs/decisions.md`.

## План

- **Формат (нужно решение автора):** `i64`, из них 32 бита на дробную часть (Q32.32). Число хранится как целое `raw`, значение равно `raw / 2^32`. Диапазон около ±2 млрд, шаг около 0,0000000002. Квадрат расстояния не переполняется до 46 км, карте этого хватит с запасом.
- Новый `crates/sim/src/fixed.rs`, в `lib.rs` строка `pub mod fixed;`.
- `pub struct Fixed { raw: i64 }`, поле закрыто. Автоматически выводятся `Clone, Copy, PartialEq, Eq, PartialOrd, Ord`: сравнение чисел совпадает со сравнением `raw`.
- Константы `ZERO`, `ONE`, `FRACTION_BITS`. Конструкторы: `from_int(i32)`, `from_ratio(numerator: i32, denominator: i32)` (так записываются дроби вроде 1/2 без float), `from_raw(i64)` и обратный `raw()` для хеша и реплея. `floor_to_int() -> i64`, `abs()`.
- Операторы `+ - * /` и унарный минус через стандартные трейты `Add`, `Sub`, `Mul`, `Div`, `Neg`. Трейты здесь необходимы: иначе формулы пришлось бы писать как `a.mul(b).add(c)`.
- Умножение и деление считают промежуточный результат в `i128`, потом возвращают в `i64`. Округление **к нулю** в обоих действиях: тогда `(-a) * b == -(a * b)`, движение влево и вправо симметрично.
- **Переполнение и деление на ноль это паника в любой сборке**, а не только в отладочной. Тихо «завернувшееся» число испортило бы мир незаметно; проверка стоит одно сравнение.
- `Debug` пишется вручную и печатает десятичную дробь (`1.5000`), считая цифры целочисленно: иначе упавший тест покажет `raw: 6442450944`.
- `proptest` (нужно согласие): `proptest = "1.12.0"` в `[dev-dependencies]` крейта `sim`. Существует, это стандартный крейт для тестов на свойствах. В саму игру не попадает, только в тесты. Его файлы `proptest-regressions/` с найденными контрпримерами коммитятся.
- `docs/decisions.md`: решение № 23 (формат и политика переполнения), вопрос уходит из «Открытых».
- Рекомендуемая модель: старшая (фиксированная точка, веха 2 целиком на ней).
- Риски: `i128` медленнее `i64`, особенно деление. Для 300 юнитов это незаметно; измерим, когда появится бюджет кадра.
- Альтернативы:
  - Q16.16 в `i32`: быстрее и компактнее, но квадрат расстояния переполняется уже на 181 м, почти каждая формула потребует ручного расширения.
  - `i64` с 16 дробными битами: без `i128` в большинстве случаев, но шаг 0,000015 даёт заметное накопление ошибки при нормализации векторов.
  - Готовый крейт `fixed`: проверен, но это дженерики и макросы внутри, а текущая линия 2.0 в статусе alpha. Автору важно читать этот код.

## Тесты

Сначала тесты, они не проходят (тип не существует), потом реализация.

Обычные:

1. `from_int(3) + from_int(4) == from_int(7)`; то же для `-`, `*`, `/` на целых.
2. `from_ratio(1, 2) * from_int(4) == from_int(2)`; `from_int(1) / from_int(4) == from_ratio(1, 4)`.
3. Округление к нулю: `from_raw(1) * from_ratio(1, 2) == ZERO` и то же для `from_raw(-1)`.
4. `floor_to_int`: 2,5 → 2; −2,5 → −3. `abs`, сравнение, унарный минус.
5. `#[should_panic]`: переполнение в `+`, в `*`, деление на ноль, `from_ratio(1, 0)`.
6. `Debug`: `from_ratio(3, 2)` печатается как `1.5000`, `from_ratio(-1, 4)` как `-0.2500`.

На свойствах (`proptest`, эталон считается в `i128` без float):

7. `a + b == b + a`, `a * b == b * a`, `(a + b) - b == a`, `(-a) * b == -(a * b)`.
8. `a * b` и `a / b` совпадают с точным результатом в `i128`, округлённым к нулю.
9. `from_raw(x).raw() == x`.

## Итог

Сделано по плану. Уточнения, которых в плане не было:

- Свойство 8 проверяется не повторением формулы из реализации, а независимо: результат умножается обратно и сравнивается с точным значением в `i128` (расхождение меньше одного шага, по модулю не больше точного).
- Вычисления вынесены в обычные функции `mul_raw`, `div_raw`, `narrow`; реализации операторов только вызывают их.
- Сообщения паники на английском (`Fixed overflow in addition`), по решению № 22.
- `Debug` отбрасывает знаки после четвёртого, а не округляет.

- Выполнено на модели: старшая (Claude Fable 5.2).
- Тесты до реализации: `cargo test -p sim` не собирался, `error[E0433]: cannot find type Fixed in this scope` (69 раз).
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy`: `Finished dev profile`; `== 3/3 Тесты`: в `sim` `test result: ok. 18 passed; 0 failed` (17 новых в `fixed::tests`), в `client` `2 passed`; `== Все проверки прошли`.

## Новое в Rust

- `impl Add for Fixed { type Output = Fixed; fn add(...) }`: реализация стандартного трейта, после неё для типа работает оператор `+`. `type Output` говорит, какого типа результат.
- `#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]`: `Copy` разрешает передавать значение без `clone()`, остальные дают `==` и `<`.
- `i128::from(x)` расширяет целое без потерь; `i64::try_from(x)` сужает и возвращает `Result`: `Ok(значение)` или `Err`, если не поместилось.
- `checked_add` и похожие: возвращают `Option`, `None` при переполнении.
- `impl fmt::Debug`: ручная реализация печати через `{:?}`; `write!` пишет в переданный приёмник, `{digits:04}` дополняет нулями до четырёх цифр.
- `[dev-dependencies]`: зависимости только для тестов.
- `#[should_panic(expected = "...")]`: тест проходит, если код упал с таким текстом.
- `proptest! { ... }`: макрос. Запись `a in диапазон` означает «подбери случайное `a`»; `prop_assert!` это `assert!`, после провала которого `proptest` ищет минимальный контрпример.

## Открытые вопросы

- Скорость `i128` (особенно деления) не измерялась.
- Перевода в `f32` для отрисовки нет: появится в клиенте в шаге 2.14.
- Нет `+=`, `-=`, умножения на целое, `min`/`max`/`clamp` как методов (`Ord` даёт `a.max(b)`). Добавляются, когда понадобятся.
- `from_ratio` принимает только `i32` и округляет к нулю: 1/3 чуть меньше настоящей трети.
- `Fixed` совпадает по имени с типом-меткой Bevy (`Time<Fixed>`). В клиенте их придётся различать при импорте (шаг 2.13).
- Спецификация вехи 2 (`spec.md`) остаётся черновиком, автором не утверждена.
- Свойства проверяются на 256 случайных наборах за запуск, набор каждый раз новый. Провал `proptest` запишет в `proptest-regressions/`, этот файл нужно закоммитить.
