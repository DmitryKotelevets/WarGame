# 2.4 Структура мира и `step()`

## Цель

В `crates/sim` есть `World`, который владеет всем состоянием симуляции, и `World::step()`, который продвигает мир ровно на один тик. Порядок работы внутри тика записан явным списком в одном месте; следующие шаги (команды, движение) будут добавлять в него по строке.

## План

- Новый `crates/sim/src/tick.rs`: `pub struct Tick(u32)` (`Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Debug`), поле закрыто. `Tick::ZERO`, `from_raw(u32)`, `raw() -> u32`, `next() -> Tick`. Переполнение в `next` это паника (при 30 тиках в секунду `u32` хватает на 4,5 года непрерывной игры). Отдельный тип, чтобы номер тика нельзя было спутать с индексом или количеством.
- Новый `crates/sim/src/world.rs`: `pub struct World { pub tick: Tick, pub units: UnitStore }` и `World::new()` (тик 0, юнитов нет). Сид появится в 2.5, очередь команд в 2.7.
- Поля `World` открыты. Системы будут обычными функциями, которым нужны сразу несколько полей мира, а клиент получает мир только по неизменяемой ссылке `&World`. Геттеры на каждое поле здесь дали бы только лишний код.
- Новый `crates/sim/src/step.rs`: `impl World { pub fn step(&mut self) }`. Отдельный файл, чтобы «одно место со списком систем» было легко найти. Сейчас в списке два пункта:
  1. `self.units.remove_marked()`: удаление отмеченных юнитов;
  2. `self.tick = self.tick.next()`.
  Места будущих систем (применение команд 2.7, движение 2.8) отмечены комментарием перед этими пунктами, без пустых функций-заглушек.
- **Смысл номера тика (нужно подтверждение):** `world.tick` это число уже выполненных шагов. Во время шага системы видят номер тика, который сейчас считается; счётчик растёт последним. Отсюда правило для 2.7: команда на тик `T` применяется в том вызове `step()`, который начинается при `world.tick == T`.
- Удаление стоит в конце списка, перед счётчиком: все системы тика видят один набор юнитов, а после `step()` снаружи (клиент, хеш) отмеченных уже нет.
- `lib.rs`: `pub mod step; pub mod tick; pub mod world;`. Клиент не трогаем: его `TickCounter` заменяется в 2.13. `SIM_VERSION` не меняется.
- Рекомендуемая модель: старшая (`step()`, структура данных мира).
- Риски: список пока почти пуст, поэтому тесты проверяют только то, что в нём есть. Правильность порядка «команды → движение → удаление» будут проверять тесты шагов 2.7 и 2.8.
- Альтернативы:
  - Список систем как массив указателей на функции `[fn(&mut World)]`: порядок виден как данные, но обычные вызовы подряд читаются проще и отлаживаются по шагам.
  - Счётчик тика растёт в начале шага: тогда первый тик имеет номер 1, а «тик 0» это только начальное состояние. Выбран рост в конце: номер тика совпадает с числом выполненных шагов и с индексом в будущем списке команд.
  - Свободная функция `step(&mut world)` вместо метода: разницы почти нет, метод короче в вызове.

## Тесты

Сначала тесты, потом реализация.

1. `Tick`: `ZERO.raw() == 0`; `next` увеличивает на 1; тики сравниваются (`ZERO < ZERO.next()`); `next` от `u32::MAX` паникует.
2. Новый мир: тик 0, юнитов нет.
3. Один `step()` увеличивает тик на 1; 100 шагов дают тик 100.
4. Юнит, отмеченный до `step()`, после шага не находится; неотмеченный остаётся с той же позицией и тем же идентификатором.
5. Отмеченный юнит удаляется именно этим шагом, а не следующим: после одного `step()` его ячейку занимает новый юнит с поколением 1.
6. `step()` в пустом мире ничего не ломает.

## Итог

Сделано по плану. Одно отличие: у `Tick` и `World` добавлен `#[derive(Default)]`, его требует clippy рядом с `World::new()` без аргументов. `Tick::default()` равен `Tick::ZERO`.

- Выполнено на модели: старшая (Claude Fable 5.2).
- Тесты до реализации: `cargo test -p sim` не собирался, `cannot find type Tick` (12 раз), `cannot find type World`, `unresolved import` обоих типов.
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy` без предупреждений; `== 3/3 Тесты`: в `sim` `test result: ok. 56 passed; 0 failed` (9 новых: 3 в `tick::tests`, 1 в `world::tests`, 5 в `step::tests`), в `client` `2 passed`; `== Все проверки прошли`.
- Размеры файлов: `tick.rs` 63 строки, `world.rs` 47, `step.rs` 100.

## Новое в Rust

- `pub struct Tick(u32);`: структура с одним безымянным полем, обёртка над числом. К полю обращаются как `self.0`, значение создаётся как `Tick(5)`. Для компилятора `Tick` и `u32` это разные типы.
- `#[derive(PartialOrd, Ord)]` на своём типе: разрешает сравнения `<` и `>`; для обёртки сравнивается число внутри.
- `#[derive(Default)]` на структуре с полями: `World::default()` собирает значение из `default()` каждого поля.
- `for _ in 0..100`: цикл, которому не нужна переменная; `_` означает «значение не используется».
- `self.units.remove_marked()` внутри `&mut self`: метод мира вызывает изменяющий метод своего поля; отдельного заимствования писать не нужно.

## Открытые вопросы

- Список в `step()` состоит из удаления и счётчика. Порядок «команды → движение → удаление» записан только комментарием, проверят его тесты шагов 2.7 и 2.8.
- Поля `World` открыты: любой код с `&mut World` может поменять `tick` в обход `step()`. Защита здесь только договорённость «клиент получает `&World`».
- `World` нельзя сравнить и напечатать (`PartialEq` и `Debug` не выведены): сравнение миров появится через хеш в 2.6.
- `World::new()` без аргументов; сид добавит шаг 2.5.
- Клиент по-прежнему считает тики своим `TickCounter`, `World` он не использует до 2.13.
- Спецификация вехи 2 всё ещё не утверждена автором.
