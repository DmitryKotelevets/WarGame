# Веха 2. Ядро симуляции и первый юнит

**Статус: черновик агента, автором не утверждён.**

## Что должно заработать

В `crates/sim` появляется настоящий мир: один юнит получает команду
«иди в точку» и доезжает до неё. Тот же сценарий без окна даёт один
и тот же хеш на macOS, Windows и Linux. Клиент показывает юнит кубом,
реплей воспроизводит прогон.

Главная цель вехи это не юнит, а фундамент: числа, идентификаторы,
порядок систем, хеш и реплей, на которых стоит всё остальное.

## Шаги

Формулировки шагов в `docs/roadmap.md`. Здесь только решения, которые
связывают шаги между собой. Подробности решаются в плане каждого шага.

- **2.1-2.2 Числа.** Свой тип `Fixed` и вектор `Vec2Fixed`, без сторонних
  крейтов в логике. Формат выбирается в шаге 2.1. Координаты мира
  двумерные (плоскость карты), высота появится вместе с картой в вехе 4.
- **2.3 Идентификаторы.** `UnitId { index, generation }`. Хранилище это
  `Vec` со свободными ячейками; обход всегда по возрастанию индекса.
- **2.4 Мир и `step()`.** Одна структура `World` владеет всем состоянием.
  `step()` вызывает системы по явному списку. Тип `Tick` живёт здесь.
- **2.5 Случайность.** Свой небольшой генератор, состояние лежит в `World`
  и входит в хеш.
- **2.6 Хеш.** Свой простой алгоритм по полям мира в фиксированном
  порядке. `std::hash` не используется: его результат не обещан
  одинаковым между версиями Rust.
- **2.7-2.8 Команды и движение.** Команда привязана к номеру тика.
  Движение по прямой с постоянной скоростью, без поиска пути и без
  столкновений.
- **2.10-2.12 Запуск без окна, детерминизм, реплей.** Реплей это сид,
  версия симуляции и список команд с тиками. Формат файла решается
  в шаге 2.12.
- **2.13-2.14 Клиент.** Временный `TickCounter` из шага 1.6 удаляется,
  в `FixedUpdate` вызывается `step()`. Перевод `Fixed` в `f32` для
  отрисовки делается на стороне клиента.

## Чего не делаем

- Карта, поиск пути, столкновения, избегание (вехи 4-5).
- Бой, здоровье, гибель юнитов. Удаление в конце тика закладывается
  в хранилище, но использовать его пока некому.
- Выделение и приказы мышью (веха 3): команда в этой вехе задаётся
  сценарием или клавишей.
- Тригонометрия на `Fixed`: появится, когда понадобится повороту.

## Зависимость от вехи 1

Шаг 2.11 сравнивает хеш между платформами в CI, поэтому шаг 1.4 (CI)
должен быть закрыт до него.

## Критерии готовности

- Куб едет в заданную точку и останавливается в ней.
- Два прогона одного сценария дают одинаковый хеш; хеш совпадает
  на трёх системах в CI.
- Записанный реплей воспроизводится и даёт тот же хеш.
- В `crates/sim` нет `f32`/`f64`, нет обхода `HashMap`/`HashSet`.
- На каждый шаг 2.1-2.14 есть заполненный файл шага.
