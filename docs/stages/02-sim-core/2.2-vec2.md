# 2.2 Вектор на `Fixed`

## Цель

В `crates/sim` есть двумерный вектор `Vec2Fixed` (точка или направление на плоскости карты) и квадратный корень для `Fixed`. Этого хватает, чтобы в шаге 2.8 посчитать расстояние до цели и направление движения.

## План

- Новый `crates/sim/src/vec2.rs`: `pub struct Vec2Fixed { pub x: Fixed, pub y: Fixed }`, выводятся `Clone, Copy, PartialEq, Eq, Debug`. Константа `ZERO`, конструкторы `new(x, y)` и `from_ints(x: i32, y: i32)`.
- Операторы `+`, `-` и унарный минус через `Add`, `Sub`, `Neg`. Умножение на число обычным методом `scale(k: Fixed)`: оператор `*` потребовал бы трейта с параметром типа, а выигрыш мал.
- `dot(other) -> Fixed`: скалярное произведение, `x1*x2 + y1*y2`. Показывает, насколько два направления совпадают.
- `perp_dot(other) -> Fixed`: `x1*y2 - y1*x2`. Знак говорит, слева или справа второй вектор от первого; понадобится для поворота и для направленной брони.
- `length_squared() -> Fixed`: для сравнения расстояний без корня.
- `length() -> Fixed`: считается сразу в `u128` из `raw`: `isqrt(x_raw² + y_raw²)`. Так квадраты не переполняются даже там, где `x * x` в `Fixed` уже упал бы (дальше 46 км), и округление одно, а не три.
- `normalize() -> Option<Vec2Fixed>`: вектор длины 1 в том же направлении. Для нулевого вектора возвращает `None`: направления у него нет, а молча вернуть ноль значило бы спрятать ошибку. Вызывающий код обязан разобрать оба случая.
- Новый `crates/sim/src/fixed_sqrt.rs`: метод `Fixed::sqrt()`, результат округляется вниз, отрицательный аргумент это паника. Отдельный файл, потому что `fixed.rs` уже 351 строка при лимите 400.
- **Корень из целого (нужно решение автора):** стандартный метод `u128::isqrt()` из Rust, а не свой алгоритм. Он точный (наибольшее `r`, для которого `r² <= n`), целочисленный и одинаков на всех платформах. Проверил: в установленном Rust 1.100 он есть.
- `crates/sim/src/lib.rs`: `pub mod fixed_sqrt;` и `pub mod vec2;`. Новых крейтов нет.
- Какая ось мира куда смотрит на экране, здесь не решается: это шаг 2.14.
- Рекомендуемая модель: старшая (веха 2 целиком на ней).
- Риски: у очень коротких векторов (длина в несколько шагов сетки) `normalize` даёт грубое направление, это свойство целых чисел. В шаге 2.8 юнит, который ближе к цели, чем проходит за тик, считается доехавшим, поэтому такие векторы нормализовать не придётся.
- Альтернативы:
  - Свой корень (побитовый алгоритм, около 15 строк): весь код перед глазами, но это повторение уже проверенной стандартной функции.
  - `normalize` для нуля паникует: проще сигнатура, но «юнит стоит в точке цели» это обычная ситуация, а не ошибка.
  - Длина через `(x*x + y*y).sqrt()` в `Fixed`: короче, но переполняется на больших расстояниях и округляет трижды.

## Тесты

Сначала тесты, потом реализация.

Обычные:

1. Сложение, вычитание, минус, `scale` на целых.
2. `dot`: (2,3)·(4,5) = 23; перпендикулярные дают 0. `perp_dot`: (1,0) и (0,1) дают 1, в обратном порядке −1, параллельные 0.
3. `length`: (3,4) → ровно 5; нулевой → 0; (3 000 000, 4 000 000) → 5 000 000, хотя квадраты в `Fixed` не помещаются. `length_squared` (3,4) → 25.
4. `normalize`: (5,0) → (1,0); (3,4) → (3/5, 4/5); нулевой → `None`.
5. `sqrt`: 4 → 2; 1/4 → 1/2; 0 → 0; отрицательное число паникует.

На свойствах (`proptest`, проверка в `u128` по `raw`):

6. `sqrt`: результат `r` наибольший из возможных: `r² <= x < (r + шаг)²`.
7. `length`: то же для суммы квадратов.
8. `normalize` для векторов длиной от 1/1024: длина результата отличается от 1 меньше чем на 2^-20, и `dot` с исходным вектором положителен.
9. `a.dot(b) == b.dot(a)`, `a.perp_dot(b) == -b.perp_dot(a)`.

## Итог

Сделано по плану, корень взят стандартный (`u128::isqrt`). Добавлен один тест сверх плана: `length` паникует, когда сама длина не помещается в `Fixed` (обе координаты у края диапазона).

- Выполнено на модели: старшая (Claude Fable 5.2).
- Тесты до реализации: `cargo test -p sim` не собирался, `cannot find type Vec2Fixed` (32 раза), `no method named sqrt` (6 раз).
- Вывод проверок (`scripts/check.sh`, код возврата 0): `== 1/3 Форматирование` без замечаний; `== 2/3 Clippy` без предупреждений; `== 3/3 Тесты`: в `sim` `test result: ok. 32 passed; 0 failed` (14 новых: 11 в `vec2::tests`, 3 в `fixed_sqrt::tests`), в `client` `2 passed`; `== Все проверки прошли`.
- Размеры файлов: `vec2.rs` 277 строк, `fixed_sqrt.rs` 69, `fixed.rs` без изменений (351).

## Новое в Rust

- `impl Fixed { ... }` в другом файле: методы типа можно дописывать в любом модуле того же крейта. Закрытое поле `raw` при этом видно только в модуле, где тип объявлен.
- `Option<Vec2Fixed>` как результат: `Some(вектор)` или `None`. Вызывающий код не получит вектор, пока не разберёт оба случая.
- `return None;`: ранний выход из функции. Последнее выражение без точки с запятой (`Some(...)`) это обычный результат.
- `x.unsigned_abs()`: модуль в беззнаковом типе (`i64` → `u64`). В отличие от `abs()`, определён и для самого маленького числа.
- `n.isqrt()`: целочисленный квадратный корень из стандартной библиотеки, округление вниз.
- `fn small_raw() -> std::ops::Range<i64>`: диапазон `a..b` это обычное значение, его можно вернуть из функции и переиспользовать.
- `prop_assume!(условие)`: `proptest` отбрасывает случайный набор, если условие ложно, и подбирает другой.
- `.expect("текст")` в тестах: достаёт значение из `Option` или `Result`, а при `None` или `Err` падает с этим текстом. В логике `sim` вместо него пишется явный `match`.

## Открытые вопросы

- У векторов длиной в несколько шагов сетки `normalize` даёт грубое направление: вектор `raw (1, 1)` нормализуется в (1, 1) с длиной 1,41. Тест на свойствах проверяет только векторы длиной от 1/1024. Шаг 2.8 должен не нормализовать такие векторы.
- `dot`, `perp_dot`, `length_squared` считаются в `Fixed` и паникуют на произведениях больше 2 млрд (векторы длиннее 46 км). `length` и `normalize` этого ограничения не имеют.
- Нет расстояния между точками как отдельного метода (`(a - b).length()`), поворота вектора, `+=`. Добавляются, когда понадобятся.
- `Fixed::sqrt` пока никем не используется: `length` считает корень напрямую. Оставлен по роадмапу.
- Имя `Vec2Fixed` взято из черновика спецификации вехи 2, который автор не утверждал.
- Скорость `isqrt` на `u128` не измерялась.
